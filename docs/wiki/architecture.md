# 架构与数据约定

## 模块职责

| 位置 | 职责 |
| --- | --- |
| `apps/extension/src/pages/option/` | 设置页与服务管理入口 |
| `apps/extension/src/pages/assistant/` | 对话、命令选择、草稿卡片 |
| `apps/extension/src/assistant/` | X 页面上下文、草稿校验、账号隔离的会话持久化 |
| `apps/extension/src/background/` | 扩展消息、服务调用、请求超时与错误转换 |
| `apps/extension/src/components/ui/` | 共享操作按钮、开关、确认交互 |
| `apps/server/src/configuration/` | 账号、配置关联、每日请求额度 |
| `apps/server/src/assistant/` | Skill 文件、目录、AI 对话、发帖权限 |
| `apps/server/src/workflows/` | 单用户／首页监听、有序动作、批次进度和恢复 |
| `apps/server/src/following/` | 按执行账号隔离的关注关系、画像与异步更新 |
| `apps/server/src/adapters/x/`、`outreach/x-client.ts` | X 内容读取、关系确认和互动请求 |
| `packages/contracts/src/` | 前后端共享类型与协议 |

新增接口先定义契约，再补服务和调用端。HTTP 路由负责参数验证，业务过程在 service / runner，数据库读写在 repository；不要把 X 请求和 AI 编排堆进 Vue 组件。

## 保存位置与离线行为

浏览器保存插件基础设置、翻译偏好、DeepL 密钥、AI 翻译指令，以及按账号分开的聊天历史和草稿。后端 SQLite 保存管理账号、凭证、配置关系、模型设置、监听和关注记录。数据库位于 `.data/fastsocial.db`，不要提交实际内容。

后端在线时，账号关联决定启用范围；未知账号不继承其他账号设置。后端离线时，基础插件使用浏览器默认配置，不按账号区分，不把离线当作数据库数据为空。Google / DeepL 基础翻译保持独立。浏览器配置迁移只迁移浏览器负责的内容。

## Skills 与画像

内置 Skill 模板：`apps/server/src/assistant/skills/{summary,post,reply}/SKILL.md`。运行时正文：`.data/skills/<名称>/SKILL.md`；数据库只管理基本信息、路径、启用状态。完整 Skill 说明任务、边界、材料处理、过程、输出和校验，设置页直接显示文件原文。备份数据库时同时备份 Skill 文件。

三个 Skill 分别处理总结、发帖、回复；账号 Profile 决定语言、身份、风格与边界。AI 翻译使用独立指令，不恢复旧 Prompt 模板管理作为新的主架构。变量采用 `{input}`、`{reply}`、`{{_tl_}}`，不添加其他同义变量。

侧边聊天是连续会话，Skill 只决定当前任务，切换 Skill 不清空上下文。普通讨论、解释和追问不强制调用 Skill，也不套用发布字数限制或读取发帖权限；自然语言明确要求生成文案或修改上一版时才匹配任务，显式 `/summary`、`/post`、`/reply` 优先。三个 Skill 全部停用时仍可普通聊天，不能绕过停用状态调用 Skill。普通对话响应不带 `skill` / `draft`，前端显示正常段落。

浏览器按账号、会话保存消息及当时的 Skill，用户消息另存页面素材快照 `reference`；生成卡片的 `context` 继续只负责账号／目标／编辑器填入校验。历史素材每条最多 16,000 字符，超出时优先保留选中内容、原帖、草稿，再保留能容纳的时间线帖子，并标记 `truncated`。请求最多携带最近 24 条消息，正文与素材合计最多 60,000 字符；优先保留对话正文，重复素材只发一次。后端按时间顺序组装历史，再附本轮页面和用户要求，不能把新页面当成旧总结的来源。旧会话的文本继续可用，但无法补回当时未保存的页面。新会话不带旧消息，账号之间不共享历史。

指定用户监听只支持单个用户。手动更新画像使用 Profile + 最新 Post 重建；任务执行时从新增证据增量更新。关注列表的画像任务异步运行，失败只影响画像状态，不把已确认的关注改成失败。监听中新关注的用户立即落库为画像待更新，本轮所有动作结束（成功或失败）后再启动画像抓取，避免额外的 Profile / Post 请求插到关注和回复之间。画像任务不继承已结束监听的请求取消条件，保持独立状态和原运行追踪 ID；手动更新画像照常启动。

## 账号和外部请求

配置主键标识自己的账号，稳定 X actor ID 隔离请求额度和关注关系，目标用户 ID 标识对方；用户名可变，不能把用户名当作稳定身份。每轮监听选定一次账号，由同一账号完成读取与动作。统一列表中的操作使用条目账号，不使用顶部筛选值。

首页、Profile、用户 Post、关注、取消关注、回复都有按账号共享的每日额度；复用现有请求入口，不能绕过额度。关系核对优先读取同一账号视角的 Profile，校验目标 ID。外部写入前持久化待确认状态；超时或结果不明保留待核对记录，不重复发送。

X 客户端统一通过 `XRequestQueue.request` 检查发送条件。监听（包括手动“立即执行一次”）、连续互关动作、自动画像任务在 `withQueuedXRequests` 范围内运行，它们的真实 X 请求跨账号、跨任务共用串行队列：上一次排队请求结束（含失败）后，至少间隔 **30 秒**。手动单次核对关系、账号测试、添加／取消关注、画像更新，以及聊天所需的 Profile 查询直接发送，不等待任务队列，也不重置该队列的间隔。操作内部的账号互斥和重复提交保护仍保留；手动请求不会绕过正在进行的同账号关系操作。AI、Telegram 和本地数据库操作不经过 X 队列。

两条发送路径都在实际请求前校验凭证、取消条件和每日额度，并原子扣除额度；排队期间不扣额度。手动超额返回 `ACCOUNT_DAILY_LIMIT` / HTTP 429，说明账号、行为、已用额度与恢复时间；聊天发帖权限查询不能吞掉该错误。手动异步画像更新先只读检查 Profile 与 Post 额度，超额立即拒绝且不改画像状态，真正发送时仍重新检查、扣除；等待期间额度变化导致的失败写入画像错误供页面展示。请求超时从发送后开始计时，服务停止取消未发送请求，不自动重发不确定的外部动作。动作层不叠加休眠；AI 与本地处理经过的时间计入任务 X 请求间隔，下一次仅等剩余时间。

回复目前使用 X 网页端 `CreateTweet` GraphQL 接口，关注／取消关注使用网页端关系接口；服务端携带账号凭证请求，不是真实浏览器点击，也不是官方开发者 API。改请求方式时同步更新这些说明。

`observability/trace.ts` 统一记录外部请求及执行链路，使用异步上下文隔离任务、账号、帖子和请求 ID。监听、手动接口、后台画像复用同一个日志入口；curl 必须在队列校验和额度检查通过后的真实发送点生成，保留实际参数，不能为了诊断额外发送请求。日志输出不参与业务成败或重试判断。按用户明确要求，生产启动入口默认保留完整凭证和原始内容，具体查看方式及边界见 [请求链路日志](development.md#请求链路日志)。

首页和指定用户监听均不按发布时间、任务创建时间或最高 Post ID 过滤，只按该任务的已处理 Post ID 去重；首次执行也判断未处理内容，不再建立仅学习而不执行的历史基线。指定用户每轮从最新页开始，帖子与回复轮流分页，合计最多 5 次 Post 分页请求（Profile 查询不占这 5 次），无下一页时提前结束；空页有游标继续读，已处理或较旧的帖子不能作为结束边界。达到 5 次是正常结束，只处理本轮获取的帖子，不把未抓到的范围标为已处理。旧 `lastSeenPostId` 仅保留作最高已读 ID 记录，不再控制筛选；重复游标仍视为读取错误。AI 监听按批分析，按条数和输入预算分批；完整验证这一批的结果后再执行动作。状态显示当前批次、本轮累计扫描数、AI 命中数和处理完成数。失败或 AI 输出截断不能悄悄跳过内容、推进监听偏移量或显示完成。

包含“关注作者”的编排仅在本次新关注成功后允许后续回复。首页快照显示已关注、当前账号关注列表已有关注，或记录为已取消关注时，直接跳过；`not_following` 是自动化的退出信号，不能由自动任务重新关注。未记录的目标在关注前读取最新 Profile，避免快照过期；其他账号的关系不影响当前账号。待核对的记录也不自动重发。只有明确的手动添加关注能覆盖退出状态。

新关注的动作结果保存 `newlyFollowed`，按 actor ID 串行确认与关注，同一作者多条帖子或并发任务只由建立新关系的那条记录继续回复。因额度不足暂缓的回复，只能凭该记录保存的新关注证明恢复；旧记录的“已经关注”不能算证明。回复生成前和排队发送前都检查是否已取消关注。跳过显示为“已跳过”，不算完成；`WorkflowRun.matched` 保留动作资格计数（关注编排需新关注成功），`aiMatched` 独立统计有效 AI 命中，`scanned` 按本轮检查的帖子 ID 去重，包含后续过滤跳过的帖子。界面统一显示 `scanned`、`aiMatched`、`completed` 的本轮累计值；复核不重复计数。回复失败不抹掉已经成功的新关注，也不自动重发。

## 改表与兼容

用户允许调整现有表结构。能保留的配置尽量保留；无法合理兼容的内容明确记录处理结果，避免让迁移包袱主导新设计。验证真实配置保留情况时只输出数量与安全字段，禁止输出 Cookie、API Key 或完整设置。历史方案不要求重新恢复已删除的功能入口。
