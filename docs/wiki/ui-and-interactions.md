# 界面与交互规范

## 操作按钮

所有操作按钮使用 `apps/extension/src/components/ui/ActionButton.vue`，只显示图标。文案保存在必填 `label` 中，组件统一生成 `title` 和 `aria-label`。不另加按钮下方说明，不恢复 `show-label`，不随页面自行改变按钮尺寸、边框、危险状态或加载样式。

```vue
<ActionButton action="profile" :label="`查看 @${user.username} 的用户画像`" @click="openProfile" />
<ActionButton action="refresh" label="更新画像" :loading="updating" :disabled="busy" @click="updateProfile" />
```

| 用途 | action |
| --- | --- |
| 添加、编辑、删除 | `add`、`edit`、`delete` |
| 测试、立即执行、重试、停止 | `test`、`run`、`retry`、`stop` |
| 用户画像、记录详情 | `profile`、`details` |
| 刷新、保存、确认、取消 | `refresh`、`save`、`confirm`、`cancel` |
| 上一页、下一页 | `previous`、`next` |
| 展开、收起全文 | `expand`、`collapse` |
| 关注、取消关注、回复、通知 | `follow`、`unfollow`、`reply`、`notify` |

新增语义先复用映射，确实不同再向组件补充 Lucide 图标。列表操作提示尽量包含目标名称，避免多个按钮都只有模糊的“编辑”。加载时按钮禁用并显示加载图标；键盘 Tab 能聚焦，Enter / Space 能触发，保留可见的 focus 样式。

导航、列表选择、Form / JSON 切换及三种 Skill 快捷卡片需要文字以便识别，允许原生 button，并分别标注 `data-ui="navigation"`、`"choice"` 或 `"shortcut"`，提供 `title`。此例外不适用于保存、测试、生成、刷新等操作。

## 开关与选择

- 布尔开关使用 `ToggleSwitch`，只点击开关本体才切换；旁边说明或空白不能触发。
- 多选用 checkbox，单选用原生 select / radio 或明确的选项组件。
- 筛选账号不改变记录归属。关注列表是一个统一列表，默认全部账号，支持账号筛选与搜索；每条记录显示自己的执行账号。
- 关注列表先汇总筛选账号的搜索结果，再排序分页；默认每页 20 条，可选 50 / 100 条。底部显示范围、总数、页码和图标翻页按钮。账号、搜索或每页条数变化时回到第一页；自动刷新保留当前页，记录减少导致页码超界时回到最后一页。翻页只读取已加载的本地结果，不调用 X 或 AI。
- 用户画像入口只保留一个人形图标，打开画像弹窗；底部用刷新图标“更新画像”，不在列表再放一个 AI 更新入口。

监听与关注列表共用 `UserPortraitDialog`。内容顺序固定为姓名与 @用户名、主页介绍、可编辑画像、可展开的画像依据；底部仅保留更新与保存图标。不要加字数计数、版本号、关系核对时间或操作说明。更新前按统一流程确认，保存本地编辑不调用 AI。更新失败时在弹窗中显示错误并保留草稿；后台列表刷新不能覆盖正在编辑的内容。画像依据中的 Post 用横线分隔，先显示可跳转的 Post ID，再显示保留段落的正文；默认最多 5 行，实际超出时显示下拉图标，悬停提示“显示全部”，展开后可“收起全文”。刷新相同内容时保留展开状态，不额外请求原帖。

## AI 与抓取二次确认

使用 `components/ui/confirm-operation.ts` 的 `confirmOperation({ title, message })`。返回 `true` 后才能发起对应请求。它是页面内的模态确认框，能用于扩展页面、嵌入聊天框与原网页内容脚本。删除等既有确认操作也复用它，不另建浏览器原生确认样式。一次确认只授权当前操作，不提供永久跳过；重复点击不共用一个批准结果。

```ts
if (busy.value) return;
if (!await confirmOperation({
  title: '确认更新画像',
  message: `使用「${account.name}」读取 @${target.username} 的 Profile 和近期 Post，再调用 AI 更新画像。是否继续？`,
})) return;
// 此处才设置任务状态并发送请求；使用确认前固定的账号与目标。
```

需要覆盖：AI 测试；手动 AI 翻译；首页／用户内容抓取；Profile 与关注关系核对；画像更新；立即执行任务；启用会自动抓取或调用 AI 的计划任务。添加关注会读取资料并生成画像，确认内容要包括这些步骤。取消关注已有独立确认弹窗，说明会先读取资料即可，不叠加相同确认。

右侧聊天框发送消息是明确例外：点击发送、Enter 发送、Skill 快捷生成、重试生成均直接执行，不弹二次确认。用户触发发送即授权本轮读取页面上下文并调用 AI；在首次异步操作前设置发送中状态，防止重复提交。保留空输入、输入法组合、账号／会话切换检查和失败后的草稿／消息恢复。填入 X 草稿仍需确认其中的 Profile 查询；其他 AI 操作不继承聊天的例外。

确认文案说明**哪个账号、什么目标、读取什么、是否调用 AI 或执行关注／回复／通知**。取消后不发对应外部请求，不清空草稿，不修改任务进度。读取本地缓存、数据库列表、历史或已有画像无需确认。已经启用的自动任务按计划运行；启用时说明持续行为，不为每批自动请求弹窗。

确认后的请求也要有状态检查：不要用当前筛选值替代条目的账号；如果账号或回复对象在确认期间变化，终止这次操作。未知结果不能通过普通“立即执行”自动重发；专门的手动重试按下面的核对流程处理。

## 页面与聊天

X 翻译浮框顶部只显示本条译文实际来源的图标：Google 翻译与 DeepL 使用对应品牌图标，AI 复用 Lucide Sparkles。统一 18px，不加文字标签、彩色底框或重复的通用翻译图标；名称放在悬停提示和无障碍名称中，允许鼠标从正文移入浮框查看提示。来源随译文保存，备用切换后展示实际成功的服务，不能按用户配置的首选渠道推断。加载、重试和失败时隐藏来源图标，切换帖子不能残留上一条的标识。

设置页复用 `settings.css` 的页面、面板、表格和工具栏样式，整体最大宽度 1280px，紧凑分组，避免大面积无意义空白。弹窗复用 `OptionDialog`；二次确认使用统一确认组件。错误出现在当前可见操作区域，不能藏在弹窗后面。

动作监听列表在执行间隔后显示“上次执行：月/日 时:分”，按浏览器本地时区展示最近一次执行结束时间；优先使用本轮状态中的 `finishedAt`，重新打开页面后回落到后端保存的 `lastCheckedAt`。尚无记录时显示“上次执行：尚未执行”，执行中保留上一轮时间，结束后随进度轮询更新。

任务失败时，原执行图标切换为重试图标，悬停显示“恢复本轮任务 + 任务名称”。点击先读取本地整轮恢复计划，再统一确认；确认框显示原轮次累计扫描、AI 命中、完成数和剩余记录数，重试不清零统计。确认说明原执行账号、未完成记录数、关注关系核对与可能的 AI 操作，以及成功后是否恢复定时启用。结果不确定的回复／通知列出目标，用户需先核对未发送，再明确确认重发；取消不改变失败状态、不发送外部请求。重试中按钮禁用，成功后错误消失、恢复普通执行图标和原计划状态，失败则保留错误与重试入口。

动作监听进度统一显示本轮累计数量：执行中为“执行中：第 N 批，扫描了 X 条，AI 命中了 Y 条，处理完成了 Z 条”；结束为“执行完成：一共扫描了 X 条，AI 命中了 Y 条，处理完成了 Z 条”。扫描按本轮获取并检查的 Post ID 去重，包含因已有关注等原因跳过的帖子；AI 命中只计有效判断结果，不用新关注成功数代替；完成只计所有动作成功的帖子。失败、额度受限或取消时保留错误原因与累计数量。

聊天采用独立扩展 iframe，保持 X 原生 Post / Reply 布局。顶部只显示图标、当前账号、新会话、历史；快捷入口为总结、发帖、回复。生成的 Post / Reply 使用保留段落的草稿卡片。复制或填入草稿不会直接发布。快捷键与鼠标走同一业务入口，中文输入法组合阶段不提交。

同一会话允许“总结 → 讨论自己的观点 → 发帖 → 修改草稿”，不用新建会话或重复粘贴前文。Skill 标记只在实际使用时显示；普通聊天展示 Markdown 段落，不伪装成发帖／回复卡片。不增加聊天模式选择器或页面素材面板。

选中 `/post`，或上一轮使用 `/post` 并继续改稿时，在聊天输入区显示“发帖模板”单选框，可选“不使用模板”及已有模板名称。选择只改变本会话的参考资料，不发送请求、不自动生成，也不强制把普通聊天切成发帖。发送期间禁用选择，失败重试使用原消息保存的模板引用；模板不可用时明确提示重新选择，保留输入。生成的发帖草稿显示实际采用的模板名称，其他消息不显示模板标记。

发帖模板的增删改位于“互动 Skills → 发帖”的独立面板，保留原 Skill 的编辑与启停入口。操作继续使用图标 `ActionButton`，列表选择标注 `data-ui="choice"`，编辑复用 `OptionDialog`，删除使用统一确认。模板管理只读写本地后端数据，不调用 AI 或 X；取消不改数据，保存失败或编辑冲突保留草稿，刷新与列表切换不得覆盖正在编辑的内容。
