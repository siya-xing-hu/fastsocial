# 开发、验证与排错

## 日常流程

1. 读根目录 `AGENTS.md` 与相关 Wiki；检查 Git 状态，定位当前调用链。
2. 明确成功后的行为，复用共享契约、组件、服务与仓库。修改外部动作时先确认账号来源、额度入口和失败状态。
3. 写源码；有行为风险时补有意义的测试，优先覆盖取消、隔离、重试、分页、异常等边界。纯样式调整通过页面验证，不堆实现镜像测试。
4. 更新行为对应的文档，运行相关检查，在模拟环境验证交互。
5. 说明结果和验证范围。需要更新运行服务时确认无任务正在执行，重建镜像并检查健康状态。

## 工具链

Node.js 24+、pnpm 11.19.0，workspace 共用根 lockfile。直接依赖添加到实际使用它的模块。

```bash
pnpm install
pnpm dev:server
pnpm dev:extension

pnpm lint:ui
pnpm test:extension
pnpm test:server
pnpm build:extension
pnpm build:server
pnpm check
```

`pnpm lint:ui` 检查操作按钮组件、必填提示、禁止文字按钮，以及保留文本的导航／选择／快捷入口声明；它已接入 `pnpm check`。`pnpm check` 同时覆盖共享契约、测试和前后端构建。此检查不能证明 AI 确认入口完整或业务正确，仍需检查真实调用链。

## 请求与交互验证

- 使用内存数据库、假账号和假的 `fetchImpl`；测试夹具明确拒绝未声明的外部 URL。
- 验证首次和旧帖均能参与监听、已处理 ID 去重、最高 ID 不过滤较小的新发现 ID、帖子／回复共用 5 页上限、空页续读、达到上限正常结束和重复游标失败。历史误过滤记录仅在日志能证明因时间跳过且没有任何执行记录时恢复；先备份，不清空全部去重记录。
- 验证任务 X 等待期间，手动单次请求、AI／本地处理仍可立即运行；手动直发仍原子扣额度，超额显示明确错误且不发送请求。AI 耗时抵扣剩余任务 X 间隔；监听的自动画像请求只能在本轮动作结束后开始，失败退出也能继续更新已成功关注用户的画像。
- X 客户端必须显式传入共享 `XRequestQueue`，使用 `request` 分派；连续任务使用 `withQueuedXRequests` 声明限流范围。普通模拟测试注入间隔为 0 的实例，限流测试注入可控时钟，验证默认 30 秒、并发排队、失败后的间隔、账号变更、额度扣除和服务停止。禁止在生产代码按测试环境关闭限流。
- 点操作后，**确认前与取消后**，对应外部请求数量均应为零；确认一次只发送一次，不能并发重复启动。
- 确认期间保留输入和记录；验证键盘发送、快捷生成、重试同样需要确认。
- 验证同一会话的总结、普通追问、发帖和改稿能连续进行；切换页面后历史素材仍属于原来的消息。普通聊天不读取发帖权限，显式 Skill 优先，停用的 Skill 不执行。恢复历史、切换账号和新会话时不串上下文；长草稿优先于历史素材占用请求预算。
- 在“全部账号”视图验证目标账户路由，在账号切换后验证旧草稿／旧对象不会落到新账号。
- 关注后回复的测试覆盖：已有关注、已取消关注、过期首页快照、同作者多帖、并发任务、账号隔离、额度暂缓和重启恢复；回复排队期间取消关注，应在发送和扣额度前跳过。分别验证扫描数、AI 命中数、新关注成功数和完成数，不能把新关注数显示为 AI 命中；重复帖子和 AI 复核不能重复累计，全部动作成功才算完成。
- 图片或页面截图检查按钮一致性、标题提示、键盘焦点、窄侧栏、弹窗滚动和错误位置。
- 构建和单元测试通过后，只因新的修改、失败或未解决问题继续扩大检查，避免重复运行没有信息增量的测试。

不要为了测试真实发送关注、取消关注、回复或 Telegram 通知。真实读取也会消耗账号额度，应优先用模拟请求定位问题。

## Docker 与数据

容器使用镜像内部代码，启动时把产物复制到宿主机 `dist/`。单独本机构建后重启旧容器会重新导出旧产物。

```bash
docker compose build fast-social
# 更新前读取 /api/workflows/runs，确认没有正在执行的任务。
docker compose up --no-build -d fast-social
curl --fail http://127.0.0.1:5127/health
```

服务更新后检查实际 `dist/extension`；浏览器重新加载已解压插件并刷新 X 页面。数据库在 `.data/`，修改表结构前使用 SQLite 支持的一致性备份并备份 `skills/`，不要在运行中只复制一个可能缺少 WAL 的数据库文件。测试启动服务时关闭 scheduler，避免测试环境自动运行真实编排。

连续任务的 X 请求间隔为 30 秒，手动单次操作不进入该队列；涉及 X 的客户端超时上限仍为 10 分钟，用于多步骤任务及账号操作互斥；AI 生成预算不包含发帖权限 Profile 查询的排队时间。监听运行接口仍立即返回任务状态，页面持续轮询本地进度，不能因请求排队长就再次发起同一操作。

## 请求链路日志

后端启动入口默认把完整请求链路写入标准输出；Docker 中可查看：

```bash
docker compose logs --no-log-prefix --tail=500 -f fast-social
```

每轮监听用 `runId` / `traceId` 关联，包含任务、执行账号、首页或用户帖子完整内容与条数、过滤原因、AI 批次和判断结果、回复正文、关注／回复／通知各步骤、最终状态与累计数量。异步画像带独立 `jobId` 并保留所属运行信息，它可能在监听结束后才完成。单独点击的接口操作也有自己的追踪 ID。

每个实际发送的 AI、X、Telegram 请求先打印 `http.request` 的步骤名称与请求 ID，紧接可直接复制的完整 `curl`。请求结束后，**接口（`url` / `method`）、请求体（`requestBody`）、请求头（`requestHeaders`）、响应体（`responseBody`）、响应头（`responseHeaders`）全部合并为同一条单行 JSON 日志**，同时包含状态码和耗时；不缩进、不分行，正文里的换行按 JSON 转义保留。用同一 `requestId` 对照 curl 与响应。没有正文或未收到响应的字段为 `null`。HTTP 200 的 X 226 和 AI 截断响应保留原文，实际重试用新的请求 ID。

流式 AI 内容仍即时转发给调用方；诊断日志在结束、取消或读流错误时一次输出已收到的全部原始流内容及请求／响应详情，避免每个数据块刷一条日志。X 队列只在前方有未完成请求或间隔不足时记录等待；空闲且间隔满足时直接打印请求。未发送的取消／额度拒绝单独记录，不生成 curl。

**用户明确要求此本地诊断日志不脱敏**，因此 curl 和原始响应可含 Cookie、CSRF、API Key、Bot Token 和完整内容。仅在本地日志保留，开发验证用模拟值，不能把真实值带入提交、文档、截图或发往其他服务。`FAST_SOCIAL_TRACE=0` 可关闭该诊断输出；`createApp` 测试实例通过 `traceSink` 显式启用，以便捕获并断言。

curl 仅打印，服务不会执行它。命令只代表当次请求；没有 `--retry`，不会自动重试。复制到终端后的手动请求直接访问远端，不经过插件确认、账号额度或 X 队列。日志从更新后产生，不能补回过去没有记录的请求。手动操作仍需确认并检查每日额度，连续任务额外经过 X 请求队列；不确定结果不重发。

日志验证要覆盖：curl 经 shell 解析后的参数与实际请求一致、单引号与换行、并发账号／任务隔离、HTTP 200 中的业务错误、网络／读流失败、流式输出与取消、日志输出故障不改变动作结果。只对模拟端点做回放，不为验证日志执行真实互动。

## 常见问题的定位顺序

| 症状 | 先检查 |
| --- | --- |
| 设置页空白、服务接口 404 | 页面错误、接口路径／契约、本地端口、当前容器版本；区分本地路由 404 与 X 404 |
| 修改代码后看不到变化 | 镜像是否重建、`dist` 是否被旧镜像覆盖、扩展是否重新加载 |
| Profile / 关注关系查询异常 | 执行账号、目标稳定 ID、响应结构、额度；不能把所有 403 / 404 都判为 Cookie 失效 |
| 显示关注失败但 X 已关注 | 查看持久化阶段，读取 Profile 核对；不要重新关注来“测试” |
| X 返回 HTTP 200、错误代码 226 | HTTP 成功不代表动作成功；226 表示请求被判定为可能的自动化或垃圾内容。先查执行记录中的账号、目标及失败步骤，在 X 检查账号状态；不能当作参数错误或直接判定 Cookie 失效，也不能连续重试验证 |
| AI 输出截断或无效 JSON | 返回的结束原因、输出预算、整批验证和失败保留偏移量；不能截取部分结果充当成功 |
| 同一页面账号或文案串用 | actor ID、会话存储键、异步响应版本、点击前固定的目标与账号 |

新增值得重复使用的排错办法时更新此表；代码变化让某条经验失效时及时修订。

X 226 的含义参考 [X 错误码说明](https://developer.x.com/en/support/twitter-api/error-troubleshooting)。每日请求额度是本地上限，不能保证平台接受上限以内的请求。动作中断时保留累计扫描、AI 命中和处理完成数量；“完成”只统计所有动作均成功的帖子，已完成的关注和未确认的回复分别保存，不回滚关注，也不自动重发回复。
