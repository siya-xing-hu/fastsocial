# 开发、验证与排错

## 日常流程

1. 读根目录 `AGENTS.md` 与相关 Wiki；检查 Git 状态，定位当前调用链。
2. 明确成功后的行为，复用共享契约、组件、服务与仓库。修改外部动作时先确认账号来源、额度入口和失败状态。
3. 写源码；有行为风险时补有意义的测试，优先覆盖取消、隔离、重试、分页、异常等边界。纯样式调整通过页面验证，不堆实现镜像测试。
4. 更新行为对应的文档，运行相关检查，在模拟环境验证交互。
5. 说明结果和验证范围。需要更新运行服务时确认无任务正在执行，重建镜像并检查健康状态。

## 工具链

Node.js 24+、pnpm 11.19.0，workspace 共用根 lockfile。直接依赖添加到实际使用它的模块。

```bash
pnpm install
pnpm dev:server
pnpm dev:extension

pnpm lint:ui
pnpm test:extension
pnpm test:server
pnpm build:extension
pnpm build:server
pnpm check
```

`pnpm lint:ui` 检查操作按钮组件、必填提示、禁止文字按钮，以及保留文本的导航／选择／快捷入口声明；它已接入 `pnpm check`。`pnpm check` 同时覆盖共享契约、测试和前后端构建。此检查不能证明 AI 确认入口完整或业务正确，仍需检查真实调用链。

## 新增 AI 操作

新增及修改 AI 操作必须复用现有公共工具，按下面的职责接入。协议、格式兼容和失败行为的细节统一维护在 [AI 公共工具与解析边界](architecture.md#ai-公共工具与解析边界)。

| 职责 | 公共入口 | 接入要求 |
| --- | --- | --- |
| 模型选择与调用 | `ai/ai-gateway.ts` 的 `AIGateway.complete`／`stream` | 业务复用现有 Gateway；浏览器通过后端接口调用，不自行请求 AI 上游 |
| 请求与协议正文提取 | `ai/openai-compatible-client.ts`、`ai/stream-reader.ts` | 统一维护协议、流式接收、结束状态、空正文、超时与截断重试，不在业务中复制客户端或流解析 |
| 结构化 JSON 的外层格式 | `ai/response-content.ts` 的 `parseAIJson` | 需要 JSON 结果时复用，不另写去代码围栏或提取 JSON 的正则 |
| 单值分类的外层格式 | `ai/response-content.ts` 的 `parseAIChoice` | 需要 Skill 等单值结果时提供允许值及明确字段，不从解释句猜测 |

接入公共解析后，各业务必须继续校验自己的字段、类型、枚举、原始字符串 ID、重复项、证据和结果完整性，再判断是否允许保存、推进进度或执行动作。不能用通用格式兼容替代业务校验，也不能把缺字段或无效结果当作未命中。普通聊天、总结、发帖、回复和翻译的生成正文按原协议返回，不套用结构化解析或剥离正文中的代码块。

遇到新的模型格式差异时，先用模拟响应复现，再在对应公共工具中增加有边界的兼容和回归测试，同时验证相关业务入口的成功及拒绝路径。新增步骤沿用既有确认、身份、超时和重试约定；不为排查额外调用真实 AI 或 X。

## 请求与交互验证

- 使用内存数据库、假账号和假的 `fetchImpl`；测试夹具明确拒绝未声明的外部 URL。
- X 自动翻译用模拟 DOM 与翻译响应验证：持续 DOM 更新时追加帖子仍能翻译，文本／语言延迟填充和虚拟列表复用会失效旧缓存；完整保留链接、换行、emoji。先悬停后返回能显示译文，失败最多重试一次，成功不重复请求；移除节点、关闭功能、切换账号时丢弃旧结果并取消重试，失焦／移出后不被迟到响应重新弹出。
- 翻译来源图标验证直接 Google／DeepL／AI、自动回退及备用窗口、AI 失败回退的实际来源；每条缓存保存自己的来源，复用节点和加载／失败状态不显示旧图标。模拟页面检查三种图标的布局、悬停提示与无障碍名称，普通文本翻译入口仍返回字符串。
- 验证指定用户只请求 Post：无新增只抓一页，遇旧边界仍处理当前页所有新帖；边界帖已删除可按较小 ID 停止，置顶／广告／会话上下文／Reply 不误触发。首次最多 5 页，后续追赶超限需保存续页并保持旧边界，重启后继续且不重复动作。测试空页、重复游标、AI／抓取／动作失败不推进，以及切换目标或账号清理续页。旧版混合最高 ID 迁移只使用该任务已处理的原帖，保留配置、画像、去重记录；无可用证据使用空边界。
- 验证任务 X 等待期间，手动单次请求、AI／本地处理仍可立即运行；手动直发仍原子扣额度，超额显示明确错误且不发送请求。AI 耗时抵扣剩余任务 X 间隔；监听中新关注用户的自动画像请求只能在本轮动作结束后开始，失败退出也能继续更新已成功关注用户的画像。
- X 客户端必须显式传入共享 `XRequestQueue`，使用 `request` 分派；连续任务使用 `withQueuedXRequests` 声明限流范围。普通模拟测试注入间隔为 0 的实例，限流测试注入可控时钟，验证默认 10 秒、并发排队、失败后的间隔、账号变更、额度扣除和服务停止。禁止在生产代码按测试环境关闭限流。
- 验证三种 AI 格式实际请求包含 `stream: true`，完整结果调用和直接流式调用共用解析器。Responses 需覆盖 `input`／`max_output_tokens` 映射、`store: false`、正文增量与完成快照不重复、终止状态、嵌套错误与 token 用量；完整 JSON 只取消息中的正文块且检查状态。覆盖 UTF-8／SSE 拆包、空帧、结束标记、错误帧、断流、总超时、截断扩容一次且丢弃残片；已收到合法 JSON 但流未正常结束时，不得推进监听进度或保存画像。设置页检查格式切换、默认端点、自定义地址保留、保存后的格式及测试确认取消路径。只有模拟请求，不用真实任务验证关注和回复。
- AI 公共层另覆盖响应头媒体类型大小写、兼容网关文本块数组及非正文过滤、Responses 零增量的完成快照、完整 JSON 缺停止原因、纯空白正文。结构化业务用同一组原始 JSON／单代码块及说明／闭合思考标签验证；多结果、截断或块外 JSON 残片必须拒绝，不能执行动作或推进进度。Skill 包装差异应得到相同单值，但解释句和多候选不猜选，停用检查仍有效。AI 服务测试、普通及流式聊天均不得将空白当成功，普通生成内容中的 JSON、代码围栏及空格仍完整保留。
- 验证画像超过 250 字、多段输出和手动编辑可以完整保存；错误／缺失的证据 ID、kind、附加字段不阻止保存正文，未知引用不写入引用字段，实际输入 Post 仍保留为画像依据。监听和关注列表弹窗一致；依据按横线分隔，Post ID 可跳转，正文默认最多 5 行，超出才提供展开／收起图标；容器宽度变化重新判断溢出，列表轮询不折叠已展开的全文。编辑／清空保留依据，失败保留草稿，轮询不覆盖编辑；更新取消不发送请求，确认只触发一次，账号隔离和后台更新并发保护有效。
- 验证指定用户监听首次、多批及后续执行均不调用画像生成、不改写已有画像；只命中输出补齐内部未命中结果，空命中会去重，非法或截断响应整批保留进度。手动更新一次只读取新 Profile 和一个用户 Post 分页，最多选取 10 条非转发帖子，执行一次画像生成，失败保留旧画像；更新不消费待监听帖子，重复点击与运行中修改目标不会提交错误画像。关注列表的新增关注自动画像行为保持不变。
- 点操作后，**确认前与取消后**，对应外部请求数量均应为零；确认一次只发送一次，不能并发重复启动。
- 需要确认的操作在确认期间保留输入和记录，键盘、快捷方式、重试经过同一确认入口。右侧聊天框例外：验证点击发送、Enter、Skill 快捷生成及重试直接请求且不弹确认；发送中重复点击不新增请求，空输入与输入法组合不提交，读取页面后账号切换会阻止发送并保留原账号草稿。填入 X 草稿仍需要确认。
- 失败任务重试验证：先验证全部 AI 命中项、去重 ID 和统计原子落库，保存失败不执行外部动作；20 条扫描、3 条命中、已完成 1 条时，第二条失败后重启应恢复第二、第三条，最终仍为原轮次 20／3／3。再次失败仍可继续，超过 100 条的队列不受历史列表截断影响；已完成所有动作但尚未提交整轮时只补交状态与游标。指定用户恢复不重新抓取或 AI 判断，全部完成才提交保存的边界及续页。确认前／取消后只读本地计划；关注实际成功但响应失败时先核对且不重复关注，不授权后续新回复；未关注才补发，已取消关注不补发；结果不确定的回复／通知须明确确认未发送。保留已成功动作、原账号和回复草稿，重复点击只启动一次；重启仍可恢复，重试失败保留原启用意图，成功清除错误并恢复计划，手动暂停的任务保持暂停。配置／身份改变和关系读取失败时不得误发。
- 验证同一会话的总结、普通追问、发帖和改稿能连续进行；切换页面后历史素材仍属于原来的消息。普通聊天不读取发帖权限，显式 Skill 优先，停用的 Skill 不执行。恢复历史、切换账号和新会话时不串上下文；长草稿优先于历史素材占用请求预算。
- 发帖参考模板用模拟数据验证增删改、重启保留、编辑版本冲突及取消不落库；管理请求不调用 AI 或 X。只有实际 `/post` 注入模板，账号 Profile 与长度校验继续生效，超长重写使用原快照。聊天选择按账号／会话保存，发送前冻结引用，重复提交、账号切换、服务离线和失败重试不串模板；删除或修改后的旧引用拒绝，保留输入。模拟页面检查模板管理弹窗、窄聊天框的模板选择、悬停提示、键盘与取消路径。
- 在“全部账号”视图验证目标账户路由，在账号切换后验证旧草稿／旧对象不会落到新账号。
- 关注后回复的测试覆盖：已有关注、已取消关注、过期首页快照、同作者多帖、并发任务、账号隔离、额度暂缓和重启恢复；回复排队期间取消关注，应在发送和扣额度前跳过。分别验证扫描数、AI 命中数、新关注成功数和完成数，不能把新关注数显示为 AI 命中；重复帖子和 AI 复核不能重复累计，全部动作成功才算完成。
- 图片或页面截图检查按钮一致性、标题提示、键盘焦点、窄侧栏、弹窗滚动和错误位置。
- 构建和单元测试通过后，只因新的修改、失败或未解决问题继续扩大检查，避免重复运行没有信息增量的测试。

不要为了测试真实发送关注、取消关注、回复或 Telegram 通知。真实读取也会消耗账号额度，应优先用模拟请求定位问题。

## Docker 与数据

容器使用镜像内部代码，启动时把产物复制到宿主机 `dist/`。单独本机构建后重启旧容器会重新导出旧产物。

```bash
docker compose build fast-social
# 更新前读取 /api/workflows/runs，确认没有正在执行的任务。
docker compose up --no-build -d fast-social
curl --fail http://127.0.0.1:5127/health
```

服务更新后检查实际 `dist/extension`；浏览器重新加载已解压插件并刷新 X 页面。数据库在 `.data/`，修改表结构前使用 SQLite 支持的一致性备份并备份 `skills/`，不要在运行中只复制一个可能缺少 WAL 的数据库文件。测试启动服务时关闭 scheduler，避免测试环境自动运行真实编排。

连续任务的 X 请求间隔为 10 秒，手动单次操作不进入该队列；涉及 X 的客户端超时上限仍为 10 分钟，用于多步骤任务及账号操作互斥；AI 生成预算不包含发帖权限 Profile 查询的排队时间。监听运行接口仍立即返回任务状态，页面持续轮询本地进度，不能因请求排队长就再次发起同一操作。

## 请求链路日志

后端启动入口默认把完整请求链路写入标准输出；Docker 中可查看：

```bash
docker compose logs --no-log-prefix --tail=500 -f fast-social
```

每轮监听用 `runId` / `traceId` 关联，包含任务、执行账号、首页或用户帖子完整内容与条数、过滤原因、AI 批次和判断结果、回复正文、关注／回复／通知各步骤、最终状态与累计数量。异步画像带独立 `jobId` 并保留所属运行信息，它可能在监听结束后才完成。单独点击的接口操作也有自己的追踪 ID。

每个实际发送的 AI、X、Telegram 请求先打印 `http.request` 的步骤名称与请求 ID，紧接可直接复制的完整 `curl`。请求结束后，**接口（`url` / `method`）、请求体（`requestBody`）、请求头（`requestHeaders`）、响应体（`responseBody`）、响应头（`responseHeaders`）全部合并为同一条单行 JSON 日志**，同时包含状态码和耗时；不缩进、不分行，正文里的换行按 JSON 转义保留。用同一 `requestId` 对照 curl 与响应。没有正文或未收到响应的字段为 `null`。HTTP 200 的 X 226 和 AI 截断响应保留原文，实际重试用新的请求 ID。

AI 请求统一以流式方式接收；`ai.stream.started` 记录响应连接建立，`ai.stream.first_text` 记录首段正文到达及耗时，不逐 token 刷日志。流式 curl 加 `--no-buffer` 便于手动观察；业务请求体仍与实际发送一致。已有直接输出的流式 AI 内容仍即时转发给调用方，完整结果调用则收齐后返回；诊断日志在结束、取消或读流错误时一次输出已收到的全部原始流内容及请求／响应详情，避免每个数据块刷一条日志。X 队列只在前方有未完成请求或间隔不足时记录等待；空闲且间隔满足时直接打印请求。未发送的取消／额度拒绝单独记录，不生成 curl。

**用户明确要求此本地诊断日志不脱敏**，因此 curl 和原始响应可含 Cookie、CSRF、API Key、Bot Token 和完整内容。仅在本地日志保留，开发验证用模拟值，不能把真实值带入提交、文档、截图或发往其他服务。`FAST_SOCIAL_TRACE=0` 可关闭该诊断输出；`createApp` 测试实例通过 `traceSink` 显式启用，以便捕获并断言。

curl 仅打印，服务不会执行它。命令只代表当次请求；没有 `--retry`，不会自动重试。复制到终端后的手动请求直接访问远端，不经过插件确认、账号额度或 X 队列。日志从更新后产生，不能补回过去没有记录的请求。手动操作仍需确认并检查每日额度，连续任务额外经过 X 请求队列；不确定结果不重发。

日志验证要覆盖：curl 经 shell 解析后的参数与实际请求一致、单引号与换行、并发账号／任务隔离、HTTP 200 中的业务错误、网络／读流失败、流式输出与取消、日志输出故障不改变动作结果。只对模拟端点做回放，不为验证日志执行真实互动。

## 常见问题的定位顺序

| 症状 | 先检查 |
| --- | --- |
| 设置页空白、服务接口 404 | 页面错误、接口路径／契约、本地端口、当前容器版本；区分本地路由 404 与 X 404 |
| 修改代码后看不到变化 | 镜像是否重建、`dist` 是否被旧镜像覆盖、扩展是否重新加载 |
| Profile / 关注关系查询异常 | 执行账号、目标稳定 ID、响应结构、额度；不能把所有 403 / 404 都判为 Cookie 失效 |
| 显示关注失败但 X 已关注 | 查看持久化阶段，读取 Profile 核对；不要重新关注来“测试” |
| X 返回 HTTP 200、错误代码 226 | HTTP 成功不代表动作成功；226 表示请求被判定为可能的自动化或垃圾内容。先查执行记录中的账号、目标及失败步骤，在 X 检查账号状态；不能当作参数错误或直接判定 Cookie 失效，也不能连续重试验证 |
| AI 输出截断或无效 JSON | 返回的结束原因、输出预算、整批验证和失败保留偏移量；不能截取部分结果充当成功 |
| AI 未返回可读取的画像正文 | 先检查已完成响应的 `memory` 是否包含正文，以及是否被模型放在 `background.identity.text` 等具名分组中；不要仅因这个提示就判断上游没有返回内容。正文解析不得把引用 ID 或元信息拼入画像，空对象与无正文结果保留原画像 |
| 同一页面账号或文案串用 | actor ID、会话存储键、异步响应版本、点击前固定的目标与账号 |

新增值得重复使用的排错办法时更新此表；代码变化让某条经验失效时及时修订。

X 226 的含义参考 [X 错误码说明](https://developer.x.com/en/support/twitter-api/error-troubleshooting)。每日请求额度是本地上限，不能保证平台接受上限以内的请求。动作中断时保留累计扫描、AI 命中和处理完成数量；“完成”只统计所有动作均成功的帖子，已完成的关注和未确认的回复分别保存，不回滚关注，也不自动重发回复。
