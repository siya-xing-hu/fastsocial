# Fast Social

Fast Social 是一个供个人使用的 X/Twitter 辅助工具，由 Chrome 插件和本地服务端组成。

## 核心功能

- 使用完整的总结、发帖、回复 Skills 辅助沟通
- 支持 OpenAI Chat Completions 与 Anthropic Messages 兼容服务
- 提供支持流式输出的 AI 聊天助手
- 支持 Google、DeepL 和 AI 翻译
- Google 翻译限流时自动切换到 DeepL，并在设定时间后重新尝试 Google
- 支持推文自动翻译、网页快捷键翻译和译文悬停展示
- 可在配置页管理模型、账号 Cookie、翻译偏好、账号 Profile 和 Skills
- 通过动作监听编排单个指定用户或账号首页的 Post，并按顺序执行关注、固定／AI 回复和 Telegram 通知；指定用户只抓 Post、不抓 Reply，按上次 Post ID 增量读取，每轮最多 5 页；指定用户画像由手动更新建立，监听只使用已保存画像，不自动生成或改写

## 项目结构

```text
apps/extension/      Chrome 插件源码、依赖和构建配置
apps/server/         本地服务端源码、依赖和构建配置
packages/contracts/  插件与服务端共享的 API 类型
dist/extension/      插件构建结果
dist/server/         服务端构建结果
.data/               本地 SQLite 数据
```

各模块管理自己的直接依赖，全仓使用一个 pnpm workspace 和一个根 `pnpm-lock.yaml`。

## Docker 一键启动

根目录执行：

```bash
docker compose up --build
```

这条命令会同时构建插件和服务端，然后：

- 在 `http://127.0.0.1:5127` 启动本地服务；
- 将 SQLite 数据持久化到 `.data/`；
- 将服务端和插件产物分别导出到 `dist/server/` 与 `dist/extension/`。

Chrome 加载已解压扩展时选择 `dist/extension`。停止服务使用：

```bash
docker compose down
```

修改代码后，运行 `docker compose up --build -d` 更新正在运行的服务和 `dist/extension`，再到浏览器扩展管理页重新加载插件。仅执行本机 `pnpm build` 或 `docker compose restart` 不会更新容器内的代码。

设置页如果提示“服务版本不兼容”，也使用上述命令更新服务，然后点击“重新连接”；浏览器本地的插件基础设置仍可使用。

如果 AI 服务运行在宿主机（例如 Ollama 或本地 API 网关），容器中的服务地址应使用 `host.docker.internal`，不能使用 `localhost` 或 `127.0.0.1`。

## 开发

开始修改前请阅读 [开发约定 AGENTS.md](AGENTS.md) 与 [开发 Wiki](docs/wiki/README.md)。Wiki 持续维护界面风格、二次确认、架构数据边界、验证与排错经验；`pnpm lint:ui` 自动检查按钮约定，已纳入 `pnpm check`。

需要 Node.js 24+ 和 pnpm。安装依赖：

```bash
pnpm install
```

分别在两个终端启动服务端和插件开发环境：

```bash
pnpm dev:server
pnpm dev:extension
```

也可以进入对应的 `apps/extension` 或 `apps/server` 目录运行各自的 `pnpm dev`、`pnpm test` 和 `pnpm build`。

## 构建与启动

```bash
pnpm build
pnpm start:server
```

Chrome 加载已解压扩展时选择 `dist/extension`。服务端产物为 `dist/server/index.js`，本地配置和数据库保存在不会被构建清理的 `.data/`。

## 浏览器之间迁移基础设置

打开“插件设置”，从 **Form** 切换到 **JSON**，点击输入框右上角的复制图标。在另一浏览器打开同一页面，粘贴并点击“保存”即可。输入框下方提供“格式化”和“重置”；重置会还原当前配置，放弃未保存的编辑。JSON 包含翻译偏好、DeepL API Key、备用时长和翻译 Prompt；保存前会校验全部字段，错误时保留原配置。切回 Form 时也会先校验并保存 JSON。

AI 服务、Skills、账号 Profile、X Cookie、Telegram 和监听规则存储在本地服务中，不属于这份浏览器基础配置；同一台电脑上的浏览器连接同一本地服务即可共享。

## 本地 AI 监控服务

项目现在包含一个仅通过宿主机 `127.0.0.1:5127` 访问的个人本地服务，用于保存 AI、账号 Cookie、账号 Profile、翻译开关、Telegram 和动作监听编排。

设置页包括插件设置、账号设置、关注列表、互动 Skills、AI 服务、连接配置和动作监听，页面整体宽度限制为 1280px。服务在线时，X 自动翻译按账号列表中的独立开关决定；未知账号不启用。服务离线时，不区分账号，使用浏览器基础设置；Google 与 DeepL 翻译仍可独立工作。

关注列表默认统一展示全部记录，支持按自己的 X 账号筛选，每条记录标明所属账号。插件关注成功后自动收录，支持搜索名称、用户名和 AI 画像、手动添加关注与取消关注；取消后保留本地记录。AI 在后台根据对方的 Profile 与最近最多 10 条 Post 生成画像，失败可以单独重试。关系核对优先使用按用户名读取的 Profile，并校验目标用户 ID；不会因一个账号的关注关系推断另一个账号的状态。首次导入本地历史关注记录后逐条核对，不同步 X 上全部已有关注。

操作按钮统一只显示图标，悬停显示名称。关注列表的人形图标打开“用户画像”，底部刷新图标用于“更新画像”。手动 AI、内容抓取、画像更新、关注关系核对和立即执行任务均先二次确认；聊天发送、快捷生成和重试使用同一确认入口。启用自动任务时说明持续行为，确认后按计划运行。

每个账号配置主语言和 Profile，描述身份、受众、表达习惯与边界，供聊天和监听回复共同使用。动作监听默认随机选择可用账号，每轮只选一次，由同一账号读取并执行后续动作；监听账号首页需指定账号。新编排默认没有动作，通过横排按钮添加关注、回复和通知。回复要素可留空，填写后优先于 Profile 的默认表达偏好，账号主语言、身份事实和边界仍然生效。

AI 翻译在“插件设置 → 翻译偏好”中选择，调用服务端默认模型。翻译指令可直接编辑并保存在浏览器，原有自定义指令保留；变量为 `{input}`（输入）和 `{{_tl_}}`（目标语言）。AI 不可用时回退至 Google / DeepL。旧模板数据仍留在数据库，已配置的旧监听引用可继续运行；编辑监听时会将指令带入回复 Skill 的回复要素。

## 侧边聊天助手

需要 Chrome 116+。重新加载 `dist/extension` 扩展并刷新 X 页面后，按 **Alt + Shift + S**（Mac：Option + Shift + S）打开／收起 X 页面内的右侧聊天框，也可点击扩展弹窗中的“打开聊天助手”。快捷键可在 `chrome://extensions/shortcuts` 修改。

- `/summary` 总结选中文字、指定原帖或已加载的帖子，不自动抓取完整时间线和图片内容。
- `/post` 根据想法、草稿或选中素材生成发帖文案。
- `/reply` 回复当前帖子；未能识别原帖时，先在 X 打开该帖子或它的回复框。

聊天框使用隔离的扩展页面浮层，不带浏览器原生侧栏工具栏，也不改动 Post / Reply 的内容布局。顶部只显示图标、当前 X 用户、新会话和历史入口。输入 `/` 后，用上下键选择 Skill、Enter 确认；仅有一个匹配时可用 Tab 补全。完成选择后 Enter 发送，Shift + Enter 换行。输入区和聊天记录会显示实际使用的 Skill。首页提供三个 Skill 的快捷方式；也可以直接描述需求，由 AI 选择任务并结合上一轮继续修改。

三个内置 Skill 位于 `apps/server/src/assistant/skills/{summary,post,reply}/SKILL.md`，各自包含发现元数据、任务边界、材料处理、执行流程和交付要求。实际正文保存到 `.data/skills/<名称>/SKILL.md`，数据库只管理基本信息、文件路径和启用状态。设置页直接展示文件原文，点击编辑后保存回同一文件；旧数据库正文会先导出，已有自定义内容保留。停用后，聊天快捷入口、命令选择和后台执行均停止使用该 Skill。备份时需要一起保存数据库和 `skills` 目录。自动选择时只使用名称与简介，选中后才加载对应正文。发帖与回复使用当前账号的长度预算，生成后通过 X 加权计数器校验，超长自动重写一次，仍不合规则报错。发帖权限统一自动识别：检测到当前账号蓝标时使用 25,000 加权字符的保守预算，未确认时按普通帖子的 280 加权字符处理。旧手动权限设置不再生效，填入 X 前会重新校验当前权限。

同一会话可先用 `/summary` 总结，再讨论自己的看法，最后用 `/post` 说“结合刚才的总结，表达我的观点”。切换 Skill 保留前文；普通追问正常聊天，不强行变成总结或文案。当前明确要求优先于历史任务。

聊天记录、使用的 Skill、页面素材和未发送草稿保存在浏览器本地，关闭侧栏后可恢复；历史支持搜索、继续、删除和撤销最近一次删除。每次 AI 请求携带最近至多 24 条消息，正文和素材合计至多 60,000 字符，优先保留正文、去除重复素材；单条历史素材最多 16,000 字符，超出会截取并标记。旧会话未保存的页面素材无法补回。每次发送会读取当前 X 页面，历史素材保持原有归属；账号切换时恢复对应账号的会话，点击新会话才开始新的讨论。发帖和回复以分段草稿卡片展示，支持复制和填入 X 原生输入框。

文案生成需要本地服务和可用默认模型。账号语言和风格在“账号设置”中编辑，未关联的账号使用通用风格。每张草稿卡片保留生成时的账号、原帖及编辑器标识，填入前再次校验；页面、账号、回复对象或手动草稿发生变化时不覆盖内容。助手不自动点击发布。原先插入 Post / Reply 的 Prompt 按钮已移除，翻译功能保持独立。

详细配置方法、凭证说明和常见错误见 [服务端说明](apps/server/README.md)。
